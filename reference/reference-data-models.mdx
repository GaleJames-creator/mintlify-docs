## Endpoint coverage for the `hitCount` field

The `hitCount` field records how many times buyers have retrieved a book's details. For its full definition (type, constraints, read-only status), see [Data models](/reference/reference-data-models#bookwithanalytics-schema-v2-only). The following table shows which endpoints include `hitCount` in their responses.

| Endpoint | `hitCount` field in response? |
| --- | --- |
| `GET /v2/books/{bookId}` | Yes |
| `GET /v2/books` | No |
| `POST /v2/books` | No |
| `DELETE /v2/books/{bookId}` | No |
| `PATCH /v2/books/{bookId}/finalize` | No |

## BaseBook schema

This is the standard `book` object returned by the create, get, and list endpoints.

```json
{
  "bookId": "string (read-only)",
  "title": "string (max 255 chars)",
  "author": "string (max 255 chars)",
  "description": "string (max 5000 chars)",
  "language": "string (ISO 639-1, e.g., en-US)",
  "publisher": "string (max 255 chars)",
  "publishedDate": "date (YYYY-MM-DD)",
  "isbn": "string (unique ISBN-10 or ISBN-13)",
  "price": "number (minimum 0.01)",
  "status": "enum (PENDING, ACTIVE, INACTIVE)",
  "coverImages": ["array of URLs (1-5 items)"],
  "genres": ["array of strings (1-5 items)"],
  "bookFormat": "enum (Paperback, Hardcover, eBook)",
  "createdDate": "datetime (ISO 8601, read-only)",
  "updatedDate": "datetime (ISO 8601, read-only)"
}
```

## BookWithAnalytics schema (v2 only)

This schema extends BaseBook with the following additional field:

```json
  "hitCount": "integer (minimum 0, read-only)"
```

### BookWithAnalytics example

For a populated BookWithAnalytics example, see the [Get a specific book](/api-reference/endpoint/getBook.mdx) `200` response, which returns a BookWithAnalytics object, including the `hitCount` field.

## Pagination schema

The pagination object used in list endpoints (e.g., `GET /v2/books`) to provide pagination details.

```json
{
  "currentPage": "integer (minimum 1)",
  "totalPages": "integer (minimum 0)",
  "totalItems": "integer (minimum 0)",
  "itemsPerPage": "integer (1-100)"
}
```

## Error response schema

The error response object returned when an API request fails.

<Note>The `validation_context` and `provided_value` fields use snake_case rather than camelCase. This is a known inconsistency in the v2 API that will be addressed in a future version. When parsing error responses, match these two fields by their exact snake_case keys.</Note>

```json
{
  "status": "error",
  "message": "string",
  "errors": [
    {
      "field": "string",
      "error": "string",
      "description": "string",
      "validation_context": {
        "rule": "string",
        "constraint": "object",
        "provided_value": "string"
      }
    }
  ]
}
```
