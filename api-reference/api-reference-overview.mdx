The BookHub Publisher API enables programmatic management of book inventory on the BookHub marketplace. This reference covers the available endpoints, request and response formats, and error handling.

## Versioning

The BookHub Publisher API uses URI path-based versioning, as shown in the following example. 

```http
https://api.bookhub.com/api/{version}/books
```
The following versions are currently available:

| Version | Endpoint URL example                    | Status  | Description                      |
|---------|----------------------------------------|---------|----------------------------------|
| `v1`    | `https://api.bookhub.com/api/v1/books` | Legacy  | Initial stable release           | 
| `v2`    | `https://api.bookhub.com/api/v2/books` | Current | Adds analytics, deactivate/delete endpoints, and reactivation via finalize; includes breaking changes from v1 |

BookHub Publisher creates a new version whenever a change would break existing integrations, so upgrading may require updating your workflow.

By including the version number in the API URL, BookHub Publisher can add new features to the latest version without breaking previous versions. Path-based versioning is simple, easy to test, supports better caching, and improves document clarity.

### Version support policy

* **v1**: Supported until December 31, 2026. After this date, v1 endpoints will return a `410 Gone` response. Migrate to BookHub Publisher API v2 before the deadline.
* **v2**: This is the current version. Use for all new integrations. Ongoing support is planned for the foreseeable future.
* **Deprecation notice**: The BookHub Publisher API provides 12 months' notice before any version is deprecated.
* **Backward compatibility**: v2 is not backward compatible with v1. Migrating to v2 requires updating your code to accommodate breaking changes.

## Authentication

All API requests require authentication using a JWT. For details, see [Authentication](/reference/reference-authentication).

## Endpoints

The following endpoints are available in v2. See v2’s [Breaking changes](/reference/reference-breaking-changes) for details.

| Endpoint | Method | Description |
|----------|--------|-------------|
| `/books` | `POST` | [Create a new book](/api-reference/endpoint/createBook) |
| `/books` | `GET` | [Get all books](/api-reference/endpoint/getAllBooks) |
| `/books/{bookId}` | `GET` | [Get a specific book](/api-reference/endpoint/getBook) |
| `/books/{bookId}` | `DELETE` | [Delete a book](/api-reference/endpoint/deleteBook) |
| `/books/{bookId}/deactivate` | `PATCH` | [Deactivate a book](/api-reference/endpoint/deactivateBook) |
| `/books/{bookId}/finalize` | `PATCH` | [Finalize a book](/api-reference/endpoint/finalizeBook) |

See [Endpoints](/api-reference/endpoint/createBook) for the interactive endpoint playground with live request examples.

## Error handling

The API returns the following status codes: `200 OK`, `201 Created`, `204 No Content`, `400 Bad Request`, `401 Unauthorized`, `404 Not Found`, `409 Conflict`, and `429 Too Many Requests`. Error responses include a `status` and `message` field and an `errors` array for field-level validation failures. For details, see [Error codes](/reference/reference-api-endpoints#error-codes).
